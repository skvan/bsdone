# 实时录入·逐位置守备局数与按位置排行（设计）

- 关联：#478 第 2 项；前置换人事务（#477）、#478 设计稿（PR #493）
- 基线：`v2.3/dev @ 7706dc0`（2026-10-29）
- 性质：详细落地设计，不含实现；目标是把“逐位置守备局数”做成**可聚合、可按位置排行、可扩展其他逐位置守备指标**的数据底座

## 一、为什么要单独记录（现状缺口）

现有排行链路已支持 `position` 参数，但**无法真正按位置拆分**：

- 打击榜：`positionFilterStat` 按 `s.position = positionCode AND fielding_gs=1` 过滤（`StatsLeadersMapper.xml:154-161`），再按 `player_id` 聚合；
- 防守榜：按 `s.position = positionCode` 过滤（`StatsLeadersMapper.xml:411-413`），`GROUP BY player_id`，位置用 `ARRAY_AGG(DISTINCT s.position)` 聚合成多值展示（`:374-407`）；
- 同一球员换位/代守后，`bs_game_player_stat` 只有一行球员统计，`position` 是最终守位，`def_inn` 是总守备局数（`GamePlayerStat.java:247-249`）；
- 实时录入只累加球员总 `fielding.ip`，不区分位置（`LiveGame.js` 的 `Ipy`），保存时直接当 `defInn` 发出。

结果：
- 不能回答“该球员作为 SS 守了多少局 / 在 SS 位置的守备率”；
- 位置筛选只是“该场最终/先发位置等于该位置”，多守位球员会被漏计或错计；
- 防守榜的位置是聚合展示值，不是可排序的维度。

## 二、目标与非目标

### 目标

1. 每场记录 **球员 × 守位** 的守备出局数（内部用 `outs` 整数，展示转棒球局数）。
2. 支撑**按位置排行**：GP / GS / INN（先落地），后续可扩展 PO/A/E/DP/TC%/捕手专项等逐位置指标。
3. 总数不丢：`bs_game_player_stat.def_inn` 继续保留，作为球员总守备局数（由逐位置汇总）。
4. 覆盖换位、代守、换投、DH、延长局；换到新位置从 0 起算，旧位置保留。
5. 聚合口径复用现有排行过滤（租户、赛事/年份、球队、gameMode、include_stats_in_ranking）。

### 非目标（本期）

- 不自动回填历史场次的逐位置数据（无法可靠还原，见第七节）。
- 不改变现有 `/stats/leaders/fielding`（球员级）的返回与筛选行为。
- 不在本期实现逐位置 PO/A/E 的实时采集（表结构预留，后续阶段）。

## 三、数据模型

### 3.1 新表：`bs_game_fielding_pos_stat`

> 相比初版设计稿的 `bs_game_fielding_inn`，本方案把表定位为“逐位置守备统计”而非“仅局数”，避免后续为 PO/A/E 再建一张同维度表。

```sql
create table bs_game_fielding_pos_stat (
  id            bigserial primary key,
  tenant_id     bigint not null,
  game_id       bigint not null,
  team_id       bigint not null,
  player_id     bigint not null,
  position      varchar(8) not null,       -- P/C/1B/2B/3B/SS/LF/CF/RF/XF...；DH/PH/EP 不落行
  outs          integer not null default 0,-- 该位置累计守备出局数（3 outs = 1.0 局）
  fielding_gs   boolean not null default false, -- 该位置是否先发（对应现有 fielding_gs 语义）
  source        varchar(16) not null default 'LIVE', -- LIVE：实时录入；DERIVED：未来可选的历史派生
  created_at    timestamp,
  updated_at    timestamp,
  unique (game_id, team_id, player_id, position)
);
create index idx_gfps_game on bs_game_fielding_pos_stat(game_id);
create index idx_gfps_player_pos on bs_game_fielding_pos_stat(tenant_id, player_id, position);
create index idx_gfps_rank on bs_game_fielding_pos_stat(tenant_id, position, player_id);
```

- 未来扩展（同表加列，不改唯一键）：`po`、`a`、`e`、`dp`、`pb`、`catcher_sb`、`catcher_cs`。
- 不加 `game_mode`：通过 `game_id → bs_game → bs_event` 关联，和现有排行一致。
- 删除策略：随比赛软删除不物理删；实时全量替换只作用于当前比赛未删除行。

### 3.2 与 `GamePlayerStat` 的关系

- `bs_game_fielding_pos_stat` 是逐位置的**事实来源**；
- `GamePlayerStat.def_inn` 是球员级**汇总**，新场次由 `sum(outs)/3` 换算后写回（保留一位棒球记法，如 10 outs → `3.1`）；
- 不新增 `def_inn_by_pos` JSON 列（无法索引/聚合，且与事实表重复）。

### 3.3 关键口径

- 每个守备出局给**当前在场**的每名守备员 +1 out（投手计入 P，DH/PH/EP 不计）。
- 换位/代守/换投：新位置从 0 起算；旧位置保留；同一球员可有多行。
- `fielding_gs`：该球员在该位置**先发**时为 true；仅先发位置一行；替补上场/换位不置 true。
- 延长局照常累计；因战术换位在同一局内多次换位，按实际所在位置分别计数。
- 总和一致性：同一球员同一场 `sum(outs)` 必须等于其实时 `fielding.ip` 的 out 数；后端保存后做校验，异常记录告警（不阻断保存）。
- 位置码统一大写并走现有位置白名单；`DH/PH/EP` 不入表；垒球位置码沿用现有规则。

## 四、采集与落库

### 4.1 前端（LiveGame）

- 球员 `stats.fielding` 增加 `byPos: { "SS": 5, "2B": 3 }`（outs）。
- `Ipy()`（每出局）在累加总 `fielding.ip` 的同时，对 `LgActiveFielders` 返回的每名在场球员按其**当前守位**累加 `byPos[pos]`。
- 换位/换人/取消 DH 无需特殊处理：计数器以位置为键，新位置自然从 0 起算。
- 撤销/恢复：`byPos` 随统计快照进/出（与第 4 项“撤销回滚统计”一并落地）；快照恢复时同步回填。
- 保存 payload（`save-live` 新增可选顶层数组）：

```json
"fieldingPositions": [
  { "teamId": 1, "playerId": 108, "position": "CF", "outs": 18, "fieldingGs": true },
  { "teamId": 1, "playerId": 111, "position": "CF", "outs": 3, "fieldingGs": false },
  { "teamId": 1, "playerId": 101, "position": "P",  "outs": 21, "fieldingGs": true }
]
```

- 语义：**出现该键即视为该场全量替换**（先删后插，同一事务）；缺省不触碰，兼容旧客户端/结果页。
- 校验：`teamId` 必须是本场主/客队；`playerId` 属于该队并过赛事名单门禁；`position` 白名单；`outs >= 0`。

### 4.2 后端

- `save-live` 在同一事务中：
  1. 校验并替换本场 `bs_game_fielding_pos_stat`；
  2. 按球员汇总 `sum(outs)` 换算并写回 `GamePlayerStat.def_inn`（仅当请求带 `fieldingPositions`）；
  3. 现有 stats upsert 不变。
- `save-result` / `import-game-result`：本期不接逐位置数据，保留 `def_inn` 手工/透传口径。
- 读取：
  - `GET /game/{gameId}/fielding-positions`（比赛维度，供箱线图/详情）：返回该场行；
  - 排行聚合见第五节。
- 幂等：全量替换天然幂等；重试不会重复累计；与 `save-live` 串行保存链兼容。

### 4.3 箱线图

- `GameDetailFieldingTable` 可选按 `player × position` 展开多行（POS 列 + 简要 INN）；无逐位置数据时回退现有单行总数。此项可后置到排行之后。

## 五、按位置排行与后续统计

### 5.1 新增排行接口（推荐）

`GET /stats/leaders/fielding-positions`

参数（复用现有排行过滤）：
`eventId/eventIds/years/teamIds/playerKeyword/gameMode/position/page/pageSize/sortProp/sortOrder`

- `position`：可选；不传则返回所有位置行（前端可分组展示），传则只返回该位置。
- 聚合：`GROUP BY player_id, position`，`sum(outs)`、`sum(fielding_gs)`、`count(distinct game_id where outs>0)`。
- 返回字段（一期）：

```json
{
  "playerId": 108, "playerName": "…", "teamId": 1, "teamName": "…",
  "position": "SS", "gp": 12, "gs": 12, "inn": "98.1",
  "source": "LIVE"
}
```

- `gp`：该位置有守备出局或先发的场次数；`gs`：该位置先发场次；`inn`：outs 转棒球局数。
- 排序白名单：`inn/gs/gp`，默认 `inn desc`；资格线建议“该位置累计 outs ≥ 9（3 局）”可配置，低样本不参与排行但可查询。
- 权限/租户/赛事范围完全复用 `StatsLeadersMapper.gameFilter` 与 `StatsLeadersApi` 现有校验。

### 5.2 与现有防守榜的关系

- 现有 `/stats/leaders/fielding` 继续按球员聚合，行为不变；其 `position` 筛选仍为“最终/先发位置近似”，在文档中标注为旧口径。
- 新接口是“按位置”的权威口径；前端位置榜切换后不再用旧接口近似。
- 后续逐位置 PO/A/E 落表后，新接口直接追加 `tc/po/a/e/dp/tcPct` 等列，不新建表、不改唯一键。

### 5.3 前端入口

- `PortalStats`：位置筛选旁增加“按位置”开关/榜单（个人榜模式下），列：球员、球队、位置、GP、GS、INN；后续加 TC%。
- 球员详情：守备卡片增加“按位置”小节（位置、局数、先发）。
- 箱线图：按位置展开（可选后置）。

## 六、历史数据与回填

- **不做自动回填**：现有 `GamePlayerStat.position` 是最终位置，`first_position` 只覆盖首次守位，事件表不含“每半局在场位置”，无法可靠拆分多守位球员。
- 排行页面展示“逐位置数据自 `<release date>` 起统计”；旧场次只在球员总榜可见。
- 可选后续（不阻塞本期）：
  - 结果页/后台提供手工逐位置局数补录（source=`MANUAL`）；
  - 对“整场只守过一个位置”的旧场次做保守派生（source=`DERIVED`），排行可过滤来源；是否启用单独决策。

## 七、实施拆分（建议）

1. **P1 数据底座**：建表 + 前端 byPos 采集 + `save-live` 全量替换 + `def_inn` 汇总回写 + `GET /game/{id}/fielding-positions`；单测/回归；不暴露排行榜。
2. **P2 按位置排行**：新排行接口 + PortalStats 位置榜 + 资格线/排序 + 文档；箱线图按位置展开可并入或紧随。
3. **P3 扩展指标**：逐位置 PO/A/E/DP/捕手专项采集与展示（同表加列）；视需求再排。
4. **P4 历史补录**（可选）：手工补录/保守派生，独立决策。

依赖：P1 的快照字段与“撤销回滚统计”（#478 第 4 项）一起设计，避免两套快照；P2 依赖 P1 上线产生数据。

## 八、测试与验收

- 前端单测：byPos 累加（出局、换位、换人、DH、延长局）、outs→局数格式、payload 序列化、撤销恢复一致。
- 后端单测：全量替换（缺键不动、带键先删后插）、球队/名单/位置校验、`def_inn` 汇总、幂等重试。
- 排行单测：按 (player, position) 聚合、位置筛选、资格线、排序、租户/赛事过滤、无数据场次不影响。
- E2E：SS 守 1 局 → 与 2B 互换 → 再守 1 局 → 保存；接口返回 SS=1 局、2B=1 局、球员总数=2；排行页按位置显示两行。
- 验收口径：同一球员多守位可分别排行；总和与 `def_inn` 一致；旧场次不出现伪造的逐位置行。

## 九、已确认决策（2026-10-29）

1. **表定位**：采用可扩展的 `bs_game_fielding_pos_stat`（预留 PO/A/E 等列）。
2. **一期排行**：GP/GS/INN；资格线为该位置累计 outs ≥ 9（3 局），默认按 INN 降序；TC% 等不在本期。
3. **前端入口**：`PortalStats` 增加「按位置」榜，展示精确位置（本期不做 IF/OF 合并视图）。
4. **历史与扩展**：不做自动回填（标注逐位置数据起始）；逐位置 PO/A/E 等扩展指标放 P3 后续排期。

落地按第八节分期执行：P1 数据底座 → P2 按位置排行/前端 → P3 扩展指标 → P4 历史补录（可选）。

1. 表定位：采用可扩展的 `bs_game_fielding_pos_stat`（推荐）还是仅局数的 `bs_game_fielding_inn`？
2. 一期排行指标：GP/GS/INN 是否够用？默认排序与资格线（建议 outs ≥ 9）是否按此定？
3. 前端入口：`PortalStats` 增加“按位置”榜（推荐）还是新建独立页面？位置展示用精确位置，还是同时提供 IF/OF 合并视图？
4. 历史数据：确认不做自动回填（推荐），仅标注数据起始；是否需要后续手工补录入口？
5. 逐位置 PO/A/E 等扩展指标：按 P3 后续排期（推荐），还是本期一起采集？
