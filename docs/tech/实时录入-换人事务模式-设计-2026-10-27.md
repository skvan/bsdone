# 实时录入·换人事务模式设计（2026-10-27）

## 背景

#444/#445 暴露的问题不是单一字段写错，而是“换人”只有前端数组变化、没有显式事件：

- 替补的 `batting_order` 从未落库；被换下者的 `position` 被清空；
- 无快照重建时，第一次保存会把当前替补阵容反推成先发，导致顺序翻转；
- 一次犹豫/纠错会留下多条中间换人历史，箱线图无法区分“真实换人”和“点错了”。

本设计把换人升级为**事务**：进入换人模式时冻结 before，结束时只比较 before/after 的净变化，一次提交；中间操作不进入历史、不进入不可再上名单。

## 交互

1. 点击「换人模式」：冻结两队 `lineup/bench/fpId/fpRow/unavailable/starterIds/slotHistory`，暂停记球/保存/结束比赛/强制换局/撤销重做。
2. 期间使用现有换人浮层、拖拽、守位互换；DH 取消通过「投手↔野手互换确认」或「拖离 DH 卡片」完成，所有中间状态只存在于页面。这些换人入口（含守备位置互换拖拽）**仅在换人模式内可用**；模式外点击守备员/打者/跑者或拖动替补卡只提示先进入换人模式，不产生任何换人动作与动画。
3. 点击「结束换人」：按打序槽位计算净变化，弹出预览（第 N 棒 A(pos) → B(pos)、守位调整、换投、取消 DH）；确认后提交，取消则继续调整。
4. 「取消换人模式」：恢复 before 整队状态，截断本次模式期间的 undo 记录。
5. 提交失败：保留模式，允许重试/取消（失败后暂不允许继续改阵容）；提交成功：撤销栈只保留进入模式前的检查点，可整体撤回本次事务。
- 小屏（≤1279px）：换人模式提供底部替补席抽屉——「防守替补/进攻替补」切换、点选球员后抽屉收起、浮动「替补席」按钮重开；点选替补再点场上守备员/打者/垒包即可完成换人（点选态优先于守备员拖拽）。
6. 取消/净零退出：恢复进入前的阵容、守位、换人史、不可再上名单、跑者对象（按 id 重新绑定到队内球员，避免统计记到副本）与本场事件日志。
7. 日志口径（#535）：模式期间换人日志全部静音，不写入事件日志/PBP，避免中间操作刷屏；提交前先回滚日志并写入 before→after 的净变化结果行（与确认弹窗同序），由提交保存流程的现场快照一并携带最终日志（只推一次）；保存失败时回滚日志并恢复静音，取消/净零不改日志。`setRunner`（空垒补跑者）属纠偏，模式内不可用（与点击空垒口径一致），因此模式内空垒不显示替补落点环、也不参与拖拽命中，避免被净变化 diff 忽略；提交进行中（`substitutionModeBusy`）拒绝再打开换人浮层或执行换人，避免入库净变化之外的本地分叉。
8. 守备轮转速记（#478 扩展）：模式横幅新增速记输入栏（输入框 + 「轮转」按钮），输入闭环守位号回车一次完成多位置轮转，如 `1341` = 1→3→4→1（投手→一垒手→二垒手→投手）。规则：仅数字 1–9；至少 3 位；首尾相同；除收尾外同一位置只出现一次；所列位置必须都有守备员。执行只改守备位置（不改打序、不换人），同步 `fpId`/守备投手行；轮转包含 1 号位且球队有 DH 时，沿用既有取消 DH 确认（确认后 DH 退场、投手进入打线，再完成轮转）；垒球 11 人（P+DH 都在打序）投手已在打线，含 1 号位按普通守位轮转处理，不取消 DH。软垒额外守位 XF（数字 10）不参与轮转；原拖拽对位换人、点选点放与旧浮层保持不变。

## 守备轮转速记（#478 扩展）

- 纯函数：`src/utils/liveSubRotation.js` — `parseFieldRotation`（闭环/去重/首尾校验）、`buildFieldRotationMoves`（位置占用校验 + 置换表）、`formatFieldRotation`（提示文案）。
- 页面接线：`LiveGame.js` 的 `applyFieldRotation()`（模式内、非提交中、非失败态）；`rotationTeamEntries()` 汇总当前守备阵容（DH 投手行按 P 参与占用校验）。
- 净变化：轮转产生的同槽守位变化落 `POSITION_CHANGE`；投手换人未被子换人覆盖时落 `PITCHING_CHANGE`；含投手且取消 DH 时按 `DH_CANCEL` 识别（垒球 11 人投手已在打序，按普通轮转处理，不取消）。
- 限制：仅作用于当前守备方；不支持 10 号位（XF）；不替代拖拽对位换人。

## 净变化口径

- 按**打序槽位**（1–12）比较，不按球员集合比较：
  - 同槽占用者变化 → `SUBSTITUTION`；
  - 同槽同一人守位变化 → `POSITION_CHANGE`；
  - `fpId` 变化且未被上述换人覆盖 → `PITCHING_CHANGE`；
  - before 有 DH、after 无 DH 且投手进打序 → `DH_CANCEL`（DH 槽位被投手占用，或 DH 移防后原投手进入野手打序）；同人仅换守位、或垒球 11 人互换后打线仍有 DH，不算取消。
- 只动板凳（加/删未上场球员）不算变化。
- 同槽 A→B→C 只记 A→C 一笔；中间 B 不进入 `slotHistory`，也不进入 `unavailable`。
- 棒次沿用 #469：先发/历史行的 `batting_order` 保留，换上者不带棒次排在下面；事件表用 `slot` 明确真实槽位。
- 被换下者：`slotHistory` 记录非先发的净 out；棒球进 `unavailable`；垒球按赛事 `softballReentry` 开关（Issue #479，默认关）：开启时不进 `unavailable`（再上须回原打序），关闭时同棒球进 `unavailable`；`lastPosition` 写入统计行的 `position` 回退值。
- 换下者展示（2026-10-28）：棒球换下后仍保留在替补席并置灰禁用（不可拖拽/点选），同时写入 `unavailable`；垒球在 `softballReentry` 关闭时同样灰显，开启时保留可选但只允许回原打序槽位。DH 队仅换投（投手无打序）同样把旧投手记入 `unavailable` 与 `lastPosition=P`，避免换下后仍能被换回。
- 替补席维护（2026-10-28）：不做自动补齐，仍由用户在阵容页手动拉人/使用现有批量添加功能维护；「追加新球员」入口已移除，不提供换下后恢复后门。换下后的球员只保留灰显，不可再操作。

## 落库

`POST /game/{id}/save-live` 新增可选 `substitutions` 数组，与 `stats` 在同一个 Spring 事务内写：

```json
{
  "game": { "...": "..." },
  "stats": [{ "teamId": 5, "playerId": 122, "position": "LF", "...": "..." }],
  "substitutions": [{
    "transactionId": "8f6c...",
    "teamId": 5,
    "inning": 3,
    "topBottom": "bottom",
    "changeType": "SUBSTITUTION",
    "slot": 8,
    "outPlayerId": 100,
    "inPlayerId": 122,
    "outPosition": "C",
    "inPosition": "LF"
  }]
}
```

- 事件表 `bs_game_substitution_event` 记录净变化；`(game_id, transaction_id, change_seq)` 唯一，重试幂等。
- 统计表仍是展示事实；`No()` 负责把当前打序/先发槽/换人历史里的人（含零统计、含已进打序的投手）留在 payload。
- 提交成功同时保存现场快照（`Pf()`），下次重进优先走快照路径，避免 `Do()` 反推先发。
- 半局结束（确认攻守交换/强制换局）自动静默保存一次统计与快照（#478 第 5 项），「直接离开」不再只剩快照而丢统计；换人提交本身已含保存。所有保存入口（自动/手动/结束比赛/保存离开）共用一条串行链，避免旧 payload 后写覆盖新状态。

## 取消 DH

- 换人模式横幅不再提供独立的「取消 DH」按钮；有 DH 的球队在横幅显示可拖拽的 DH 卡片。
- 两种入口：
  1. **投手↔野手互换**：确认后先取消 DH（DH 槽位换成当前守备投手，投手 `position=P` 进入打序，DH 落到板凳并保留 `lastPosition=DH`；`fpId` 指向该投手、`fpRow` 清空），再交换两人的守备位置（原投手去野手位置，原野手接任 P 并保留自己的打击棒次）。
  2. **拖离 DH 卡片**：把 DH 卡片拖出横幅卡片槽位，等同取消 DH；新投手已上场时也直接对当前守备投手执行同一动作。垒球 11 人阵容不适用（投手已在打序，无法再让投手进打序），提示「当前投手已在打序中，无法取消 DH；可将 DH 拖到守备位交换位置」。
- 垒球 11 人（P+DH 都在打序）：DH 卡片拖到守备位（含 P）为普通守位互换（DH 与目标守备员交换守位，打线仍保留 DH），不取消 DH；P↔野手互换同样只交换守位。
- 规则门控（MLB OBR 5.11(a)(2)/(8)/(14)，仅棒球）：
  - 先发 DH 至少完成一次打击，除非对方已经换投；未满足时弹出规则提醒，由记录员确认是否仍然取消（实时数据无法覆盖所有换投细节，因此不静默放行）。
  - 投手从投手丘转到其他守备位置、或守备球员上投手丘，均终止 DH；普通从替补席换投不终止 DH。
- 结束换人时 diff 识别为 `DH_CANCEL`：before 有 DH、after 无 DH，且投手进打序；即使随后完成 P↔野手互换（DH 槽位的换上者已是原投手、位置可能为非 P），仍按「DH 槽位由非 DH 占用」识别。DH 移防导致原投手进入野手打序的路径同样识别；垒球 11 人互换后打线仍有 DH，不识别。
- `No()` 的打击行过滤保留“当前打序里的投手”，因此箱线图同时有他的打击行与投手行。
- 后端允许 `DH_CANCEL`；不在此 PR 扩展 `save-result` 的 P/DH 强校验（后续 #130 勾稽项）。

## 边界与限制

- 模式期间禁止记球/换局；若离场，离开守卫会先取消模式并提示。
- 一次事务不还原中间合法多次换人的顺序；如需保留顺序，应拆成多次事务。
- 存量已被错位固化的 `batting_order`/`position` 不在本设计修复范围。
- `lineup_slot` 暂未加到统计行；事件表承担槽位事实，箱线图当前仍按 #469 的 `listOrder/batting_order` 展示。
- 二刀流/10–12 棒遗留数据的先发识别仍沿用 #461 的兜底；后续在 #130 勾稽中补强。
