# 个人驾驶舱评价算法

个人驾驶舱「总体评价」模块的算法说明：三张六轴雷达（打击 / 守备 / 投球）、分项 0–100 评分与总体评分。

> 口径：**全租户生涯**。对比样本为当前租户、同一运动类型（棒球 / 垒球不混算）、有有效生涯数据的全部球员；雷达与总体评分**不随顶部球队 / 赛事筛选变化**，也不跨租户比较。
>
> 本文以代码为准，对应实现：
> - `bsball-backend/src/main/java/com/bsball/service/ClubhouseEvaluationService.java`
> - `bsball-backend/src/main/java/com/bsball/service/ClubhouseRatingSupport.java`
> - `bsball-frontend/src/views/portal/PortalClubhouse.vue`（总体评价模块）

## 1. 计算流程

1. **可用性**：打击需有打席或打数，投球需有投球局，守备需有出场或守备机会；再达到展示门槛才生成该分项（见第 7 节）。
2. **取对比池**：从全租户排行榜取当前运动类型的前 500 名球员（打击按 PA、投球按 IP、守备按守备局数降序），再按展示门槛过滤，得到该分项的对比池。
3. **百分位**：每个轴把本人原始值换算成对比池内 0–100 百分位；越低越好的指标反向换算。
4. **分项评分**：质量轴百分位按固定权重加权，得到分项原始分；缺失轴的权重重归一化。
5. **小样本收缩**：按本人样本量与稳定门槛计算可靠性，把原始分向 50 分收缩，四舍五入并截断到 0–100，得到分项评分与等级。
6. **总体评分**：按角色权重合并各分项评分，权重在可用分项间归一化；总体可靠性同样按权重加权。

雷达只呈现**能力轮廓**，不是总分：雷达轴是展示指标，分项评分只取质量轴加权，总体评分再按角色合并，三者都不取雷达面积。

## 2. 六轴定义与方向

每张卡固定 6 轴，顺序固定；轴值为对比池百分位（0–100）。

| 卡片 | 轴 1 | 轴 2 | 轴 3 | 轴 4 | 轴 5 | 轴 6 |
|---|---|---|---|---|---|---|
| 打击 | AVG 打击率 ↑ | OBP 上垒率 ↑ | SLG 长打率 ↑ | OPS 整体攻击 ↑ | RBI 打点 ↑ | SB 盗垒 ↑ |
| 守备 | FPCT 守备率 ↑ | TC/G 场均守备机会 ↑ | PO/G 场均刺杀 ↑ | A/G 场均助杀 ↑ | DP/G 场均双杀 ↑ | RF/9 守备范围 ↑ |
| 投球 | ERA 防御率 ↓ | WHIP 被上垒率 ↓ | K/9 夺三振率 ↑ | BB/9 保送率 ↓ | HR/9 本垒打率 ↓ | IP 投球局数 ↑ |

- ↑ 表示越高越好；↓ 表示**越低越好**，服务端先反向再计算百分位。
- 投球卡始终返回，未达展示门槛（3 IP）时 `available=false`；打击、守备卡同样固定返回，样本不足时给出原因。
- 分项评分不使用全部六轴：打击的 AVG、OPS 只展示不计分；投球的 ERA、HR/9、IP 只展示或作样本量，不计入质量权重（见第 5 节）。
- IP 轴展示保留棒球记法（`5.2` 表示 5⅔ 局），百分位与所有比率计算都换算为十进制局数（出局数 ÷ 3）。

## 3. 百分位与 50 基准

设对比池共有 `N` 个有效值（升序），本人原始值为 `x`：

```text
higherBetter = true  ：less = 池中 < x 的个数
higherBetter = false ：less = 池中 > x 的个数（反向指标）
equal = 池中与 x 相等的个数
rank  = less + max(0, equal − 1) / 2
percentile = round(rank × 100 / (N − 1))，并截断到 0–100
```

- 并列值取平均名次。
- `N = 1` 时返回 50，表示缺少可比对象。
- 对比池为空时返回 0。
- **50 为中位基准**：同组中位水平约为 50；高于 50 优于中位，低于 50 弱于中位。前端雷达画 20/40/60/80/100 五个同心环，50 位于 40 与 60 环之间，不单独绘制基准环。
- 本人若因池上限（500）或过滤不在池内，仍用其生涯统计构造本人行，并以该池计算百分位；本人若在池内则直接使用池内行。

## 4. wOBA（参考 wOBA）

打击质量第一权重使用固定业余近似权重的 wOBA：

```text
wOBA = (0.70×BB + 0.70×HBP + 0.90×1B + 1.25×2B + 1.60×3B
        + 2.00×HR + 0.20×SB − 0.40×CS)
       / (AB + BB − IBB + SF + HBP)
```

- **场内本垒打（insideParkHr）按本垒打权重 2.00 计入 HR**，且不计入一垒安打；HR/9 同样包含场内本垒打。
- 分母不为正时返回 0。
- 权重为固定值，不按赛季、联赛或球场校准，因此界面与接口统一标注「参考 wOBA」。
- wOBA 不进入雷达轴（避免与 OPS 重复），只作为打击分项的质量项。

## 5. FIP（参考 FIP）

```text
FIP = (13×HR + 3×(BB + HBP) − 2×SO) / IP + C
```

- HR 含普通本垒打与场内本垒打；`IP` 使用十进制局数；无有效投球局时返回 0。
- `C` 为**租户常数**（当前租户、同一运动类型）：先汇总整个投球池的 HR / BB / HBP / SO / ER / IP（只累加有投球局的行），再计算

  ```text
  C = 联盟平均 ERA − 联盟原始 FIP
    = (9 × ΣER / ΣIP) − ((13×ΣHR + 3×(ΣBB + ΣHBP) − 2×ΣSO) / ΣIP)
  ```

  使联盟平均 FIP 对齐联盟平均 ERA。常数用池内合计值计算，不做逐人平均。
- 与百分位池不同，`C` 使用**未按 3 局展示门槛过滤**的完整投球池；池空或无有效投球局时 `C = 0`。
- 所有投手使用同一常数计算 FIP 后再取百分位；界面与接口统一标注「参考 FIP」，并展示 `FIP（C=常数）`。
- FIP 不进入雷达轴（避免与 ERA 重复），只作为投球分项的质量项。

## 6. 权重

### 6.1 分项质量权重

| 打击轴 | 权重 | 投球轴 | 权重 | 守备轴 | 权重 |
|---|---:|---|---:|---|---:|
| wOBA | 0.50 | FIP（反向） | 0.50 | FPCT | 0.30 |
| OBP | 0.20 | K/9 | 0.20 | TC/G | 0.15 |
| SLG | 0.15 | BB/9（反向） | 0.15 | PO/G | 0.15 |
| RBI | 0.10 | WHIP（反向） | 0.15 | A/G | 0.15 |
| SB | 0.05 | — | — | DP/G | 0.10 |
| — | — | — | — | RF/9 | 0.15 |

- 分项原始分 = Σ(轴百分位 × 权重) / Σ(权重)，只统计对比池非空的轴；全部轴都无池时原始分为 50。
- 守备 6 轴全部计分，权重合计 1.00；打击 5 项、投球 4 项质量权重也各自合计 1.00。

### 6.2 角色与总体权重

| 角色 | 判定（按顺序） | 打击 | 投球 | 守备 |
|---|---|---:|---:|---:|
| 二刀流 `TWO_WAY` | 投球可用且打击可用，且本人 PA ≥ 50、IP ≥ 15 | 0.40 | 0.40 | 0.20 |
| 投手 `PITCHER`（打击可用） | 投球可用，未满足二刀流；打击达到展示门槛 | 0.15 | 0.70 | 0.15 |
| 投手 `PITCHER`（打击不可用） | 投球可用，打击未达展示门槛 | — | 0.80 | 0.20 |
| 野手 `POSITION_PLAYER` | 投球不可用（含不足 3 IP） | 0.55 | — | 0.45 |

- 投球达到展示门槛（3 IP）才按投手 / 二刀流处理；否则按野手处理。
- **总体权重在可用分项间重新归一化**：例如投手打击不可用时，0.80 / 0.20 本身合计 1.00；野手若打击也不可用，则守备权重归一化为 1.00。
- 总体评分 = Σ(分项评分 × 归一化权重)，四舍五入为整数；总体可靠性 = Σ(分项可靠性 × 归一化权重)；接口 `overall.weights` 返回归一化后的实际权重（保留 3 位小数）。
- 没有任何可用分项时，`overall.score = null`、`available = false`。

## 7. 守位分组与小样本

### 7.1 守位组

| 守位组 | 包含守位 |
|---|---|
| `C` | C |
| `1B` | 1B |
| `INF` | 2B、3B、SS |
| `OF` | LF、CF、RF、OF |
| `DH` | DH |
| `P` | P |
| `UTIL` | 其他或无法识别的守位 |

- 守位字符串忽略大小写与首尾空白；多守位行以顿号或逗号分隔（如 `CF、LF`），**任一守位命中目标组即视为组内**。
- 本人对比组优先取主要守位（球员档案守位，缺失时取统计行守位）中第一个可识别的组；全部无法识别时归 `UTIL`。
- 组内有效球员（达到 6 守备局）**≥ 5 人**时只在同组内计算守备百分位；**不足 5 人时回退到全体守备百分位**，并在卡片 `note` 标注「未按守位分组」。
- 已知偏差：`P` 与 `DH` 天然样本少，常触发回退；DH 的守备数据本身稀少，回退后与其他守位混比，仅供参考。

### 7.2 门槛、可靠性与收缩

| 分项 | 展示门槛 | 稳定门槛 | 样本单位 | 可靠性 |
|---|---:|---:|---|---|
| 打击 | 10 PA | 50 PA | 打席 PA | `min(1, PA / 50)` |
| 投球 | 3 IP | 15 IP | 投球局 IP | `min(1, IP / 15)` |
| 守备 | 6 守备局 | 30 守备局 | 守备局 INN | `min(1, INN / 30)` |

```text
reliability = min(1, 样本量 / 稳定门槛)        // 截断到 0–1；样本 ≤ 0 或门槛 ≤ 0 时为 0
adjusted_score = 50 + (raw_score − 50) × reliability
score = round(clamp(adjusted_score, 0, 100))
```

- 未达展示门槛：该分项 `available=false`、不参与总体评分，`reason` 给出原因。
- 达到展示门槛但未达稳定门槛：评分向 50 收缩，`confidenceLabel = 参考值`。
- 达到稳定门槛：`reliability = 1`、不收缩，`confidenceLabel = 样本充足`。
- `reliability = 0`（无有效样本）时为 `样本不足`。
- 投球 / 守备的样本量在内部与阈值比较时都使用十进制局数（`5.2` → 5.667 局）。

### 7.3 0–100 分与等级

分项与总体均按 0–100 展示（不改用 20–80 主显示），等级映射：

| 分数 | ≥90 | ≥85 | ≥80 | ≥75 | ≥70 | ≥60 | ≥50 | <50 |
|---|---|---|---|---|---|---|---|---|
| 等级 | S | A+ | A | B+ | B | C+ | C | D |

## 8. 样本字段语义

| 字段 | 位置 | 含义 |
|---|---|---|
| `sampleSize` | 卡片 | **对比池人数**（该分项参与百分位计算的球员数），不是本人样本量；守备为实际参与比较的池人数（同守位组或回退后的全体）。 |
| `sampleSize` | `overall` | 对象 `{ batting, pitching, fielding }`，分别为三个分项的**本人样本量**（PA / IP / INN）。 |
| `ownSample` | 卡片 | **本人样本量**：打击为 PA（整数）；投球、守备为十进制局数（保留 1 位小数）。 |
| `sampleUnit` | 卡片 | 本人样本单位：`PA` / `IP` / `INN`。 |
| `reliability` | 卡片 / `overall` | 0–1 可靠性系数，保留 2 位小数。 |
| `minSample` | `evaluation` | 展示门槛对象：`{ batting: 10, pitching: 3, fielding: 6 }`。 |

前端展示时需同时给出「样本池 N 人」与「本人 X PA / X IP / X 局」，避免只看雷达形状、不看样本量。

## 9. 已知限制

- **无球场与联盟校正**：不区分主场 / 客场、球场打者友好度，也不按联赛强度调整；跨联赛比较时百分位只反映本租户池内相对位置。
- **wOBA / FIP 为固定近似**：wOBA 权重固定、不按赛季或联赛校准；FIP 常数虽由租户池反推，但池较小时常数波动大；两者都标注为「参考」。
- **对比池上限 500**：每个分项只取全租户排行榜前 500 名（按 PA / IP / 守备局降序），规模更大的租户中，池外球员不参与百分位；本人不在池内时仍用生涯统计计算，但对比分布不完全。
- **守位组限制**：`P`、`DH` 样本少，常回退全体并标注「未按守位分组」；`UTIL` 为兜底组；多守位球员只按主要守位归组，其他守位的守备价值不会拆分。
- **FIP 常数口径**：常数使用未过滤的完整投球池，与百分位池（≥ 3 IP）不完全一致；ERA 使用统计行的 `er` 字段，依赖记分数据完整。
- **无缓存**：每次驾驶舱聚合都会按需查询三个排行榜（仅对达到展示门槛的分项查询），池上限降低开销，但高并发下仍有数据库压力。
- **无历史版本**：评分随数据累计实时变化，不保存历史快照，无法回看「上月评分」。
- 数据依赖系统内已记录的比赛日志；系统外历史无法补齐，早期样本少时评分会明显向 50 收缩。

## 10. 参考来源

- [Baseball Savant Percentile Rankings](https://baseballsavant.mlb.com/leaderboard/percentile-rankings)：用同群百分位呈现球员能力轮廓，避免不同量纲指标直接相加。
- [How MLB The Show rates players](https://www.mlb.com/news/how-mlb-the-show-rates-players)：游戏总体评分按位置与能力维度加权，而非简单平均。
- [OOTP Player Ratings](https://manuals.ootpdevelopments.com/index.php?man=ootp16&page=player_ratings) / [Ratings Overview](https://manuals.ootpdevelopments.com/index.php?man=ootp16&page=ratings_overview)：位置相关的评分维度与 20–80 刻度。
- [FanGraphs：wRC+](https://library.fangraphs.com/offense/wrc/)：加权进攻指标以联盟平均为 100，说明「加权 + 基准」的常用做法。
- [FanGraphs：ERA](https://library.fangraphs.com/pitching/era/) / [FIP](https://library.fangraphs.com/pitching/fip/)：FIP 以 HR、BB、HBP、SO 构造与 ERA 同刻度的防御指标。
- [FanGraphs：The 20–80 Scouting Scale](https://blogs.fangraphs.com/scouting-explained-the-20-80-scouting-scale/)：20–80 球探刻度的含义；本项目主显示仍为 0–100，仅借用其分级思路。
- [FanGraphs：Sample Size](https://library.fangraphs.com/principles/sample-size/)：小样本波动与稳定门槛的依据。
- [FanGraphs：Positional Adjustment](https://library.fangraphs.com/misc/war/positional-adjustment/)：不同守位的守备数据不可直接同尺度比较，需按守位分组或调整。
