# 垒球再上场特殊规则设计（2026-11-10）

> Issue #479。基线：`origin/main` + 换人模式 XF/DH 修复（PR #643）。本文以代码为准。

## 背景

棒球规则下被换下球员不可再上场；垒球允许换下后再上场，且须回到原打序槽位。原实现只用赛制硬编码（`sport === 'SOFTBALL'` 时不移入不可再上名单），没有开关、没有同棒次约束，且默认行为无法按赛事关闭。

## 产品口径（已确认）

- **开关位置**：赛事级特殊规则区，沿用 `extraBatter` / `forceHalf` / `ohtaniRule` 的存储与联赛「特殊规则能力」门禁；仅 `gameMode=SOFTBALL` 的赛事显示。该赛事下所有比赛继承。
- **默认状态**：新建垒球赛事默认关闭；存量无规则垒球赛事同样按关闭生效。
- **次数**：不设限，开关只控制允许/禁止。
- **同棒次**：开启时，换下球员再上场必须回到其原打序槽位；目标槽位不符或无法定位时提示并阻止。原槽位已被占用时按同槽换人处理（现任球员被换下）。
- **关闭时**：垒球按棒球口径，换下球员进不可再上名单、替补席灰显不可选。
- **棒球**：恒不可再上，不受本开关影响。

## 数据与后端

- 规则键：DB `softball_reentry`，API `softballReentry`，默认 `false`。
- 存储：`bs_event_special_rule`（唯一约束 `(event_id, rule_key)`）；规则键为字符串行，新增键无需 DDL。
- `EventSpecialRuleService`：接入 `API_TO_DB_KEY`、`DEFAULTS`、`getEffective`、`validateRules`。
- `EventService.get`：`specialRules` 响应增加 `softballReentry`（默认 false）；创建/更新沿用同一事务写入。
- 门禁：启用联赛收费能力 `specialRulesEnabled` 才能为无既有规则的赛事写入；已有规则的赛事在能力关闭后仍保留并可编辑。

## 前端

### 赛事编辑

- `EventSpecialRuleFields.vue` 增加 `gameMode` prop；`v-if="gameMode === 'SOFTBALL'"` 才显示「垒球再上场」开关，默认关。
- `Events.js`：表单初值 / 详情加载 / 保存映射接入 `softballReentry`；保存时仅垒球赛事携带该键。

### 实时录入

- 读取 `event.specialRules.softballReentry`（默认 false），同时要求 `gameMode === 'SOFTBALL'` 才生效。
- `Ki()`：开关开时跳过不可再上；关闭时同棒球记入 `unavailable`。
- 替补席 `buildLiveBenchItems(..., reentryAllowed)`：关闭时已换下球员灰显；旧换人浮层的 `Yi()` 同样按开关过滤。
- 提交净状态 `applyNetTeamState(..., { reentryAllowed })`：关闭时把换下者写入 `unavailable`，开启时不写。
- 同棒次校验（纯函数 `originalLineupSlot` / `validateReentrySlot`）：
  - 原槽位：先发槽（`starterIds`）优先，其次换人史（`slotHistory`）；纯板凳返回 null（不限制）。
  - 在 `cc()` 的替补上场路径（守备替补、代打、代跑）校验：目标槽位 = 被换下球员所在 lineup 槽位；与原槽位不符提示「垒球再上场必须回到原打序（第 N 棒）」并阻止；无法定位（如仅守备投手行）提示「无法确认该球员的原打序槽位」。
  - 守备员之间的守位互换不触发再上场校验。

### 关闭态兜底

- **有效不可再上名单**：显式 `unavailable` + 替补席上曾出现在先发槽（`starterIds`）或换人史（`slotHistory`）的前打序球员。读时回填，兼容历史垒球快照未写 `unavailable` 的场次；关闭态的替补席灰显、旧浮层过滤与 `cc()` 拦截都使用该有效名单。换人模式内按**进入前**状态计算，刚换下的球员不立即灰显（允许犹豫后拖回原槽位），真正再上由提交时净 diff 拦截。
- **同一事务内拦截**：关闭再上场时，被换下者不得在同一换人事务内以其他槽位/投手身份再上（结束换人时检查净 diff 是否同时含该人的 out/in）；避免 `unavailable` 在提交前冻结而被绕过。

## 事件与统计

- 不新增事件类型：再上场形成同槽的第二笔 `SUBSTITUTION` 事件（`out/in` 为当前占用者与再上者），事件表按事务顺序可审计。
- 同一球员沿用同一统计行，不新建重复行；`position` 由现有保存链路回写。

## 测试

- 单测：规则默认 false / 写入回读 / 未知键拒绝；替补席灰显与空席文案；`applyNetTeamState` 开关开/关；`originalLineupSlot` 与 `validateReentrySlot` 同槽/错槽/纯板凳/无法定位。
- 静态护栏：赛事表单仅垒球显示、默认关；`LiveGame` 的规则读取、`Ki`、替补席、净状态、`cc()` 同棒次接线。
- 本地 E2E：垒球 10 人，开启时 CF 换下球员回到 CF 成功、拖到 LF 被拦截；关闭时换下球员替补席灰显并进入不可再上快照。

## 边界

- 不做每场覆盖；不做次数限制；不新增 `REENTRY` 事件类型。
- 仅守备投手行（无打序）的再上场会被「无法确认原打序」拦截，需从原打序位置或守备位换人。
- 存量垒球赛事默认关闭会改变现有「换下可再上」默认体验，属已确认口径；需要再上的赛事在赛事编辑中手动开启。
