# 自责分绝对重算（后端）

- 对应 Issue：#436（父议题 #149）
- 日期：2026-10-25
- 范围：`bsball-backend`（PR B）；前端台账见 PR A 的 `docs/tech/实时录入-得分台账与自责分重算-设计-2026-10-25.md`

## 一、背景

原实现用 `applyPitcherStatDeltas` 按「旧判定 -1、新判定 +1」的增量维护投手 `pitch_r / er / unearned_r / pending_r`。增量维护有三个问题：

1. 前端漏记或重复记账时，误差会永久沉淀，重建半局也无法回到正确值。
2. 半局重建只处理当前半局判定，历史膨胀不会被发现。
3. 人工覆核只调整单条判定的增量，无法修正存量错误。

场次 245 的 `ER > R` 即由存量膨胀造成。

## 二、实现

触发点不变：

- `replaceHalfInning`：重建半局、写入新事件与新判定后触发。
- `overrideDecision`：人工覆核单条判定后触发。

两者统一调用 `recomputePitcherStats(tenantId, gameId, fallbackTeamId)`：

1. `EarnedRunDecisionRepository.findByTenantIdAndGameId` 读取该场全部逐分判定。
2. 按 `responsible_pitcher_id` 聚合：R = 判定条数，ER/UER/PENDING 按状态计数。
3. `GamePlayerStatRepository.findByGameId` 取该租户全部投手行；有判定的投手以聚合值**绝对覆盖**四个字段，不再累加。
4. 缺少投手行时补建：优先用同一球员在其它统计行上的 `team_id`，找不到再用当前半局守备方 `fieldingTeamId`；两者都没有则抛错，避免写入无球队的行。
5. 返回全投手绝对值（含本次未触及的投手），前端按绝对值幂等覆盖展示。

未出现在任何判定中的投手行保持原值，避免把未登板/占位行清零。

## 三、不变量

绝对重算后必须同时满足：

- PostgreSQL 应用列：`pitchr = er + unearnedr + COALESCE(pendingr, 0)`
- 若新列存在：`pitch_r = er + unearned_r + COALESCE(pending_r, 0)`；两套列必须一致
- 每名投手 `er <= pitchr`（新列同理）
- 同一批判定重复重算结果不变（幂等）

单元测试覆盖：同半局重复重建、历史膨胀修正（6 R / 14 ER → 2 R / 1 ER / 1 UER）、缺失投手行补建、人工覆核后绝对重算。

## 四、验证

- `mvn test`：804 项全部通过
- 覆盖类：`EarnedRunReconstructionServiceTest`

## 五、限制与后续

- 仅对已有 ER 引擎事件的场次生效；没有引擎行的场次仍由既有守卫处理。
- 判定本身缺失（playEvent 漏记）时，绝对重算只会与判定一致，不会凭空补分；这类场次由生产数据修复（PR C）单独核对。
- 生产历史数据不随本 PR 修改，写库需要单独批准、备份与回滚方案。

## 六、列名与验收口径（2026-10-26 补记）

PostgreSQL 上比赛详情/`GamePlayerStat` 实体实际读写旧列（无下划线）：

- `pitchr / unearnedr / pendingr / earnedr`
- `pitchh / pitch_bbhp`

聚合 Mapper 的 `pitchR` 在 PostgreSQL 分支也使用 `pitchr`；`unearned_r` / `pending_r` 目前仍直接读新列，所以两套列必须保持一致。2026-10-25 的历史数据修复只写了新列，导致 `er` 已更新、页面 R 仍是旧值（场次 245 出现 ER > R）。2026-10-26 已对 12 场、53 个投手行中的 36 行把旧列同步为逐分判定重算值：

- 备份：`/root/er-repair-436-20261025/stat-before-legacy-sync-20261026.dump`，库内 `er_repair_436_legacy_20261026.stat`（53 行）。
- 变更：`pitchr = pitch_r`、`unearnedr = unearned_r`、`pendingr = pending_r`；事务内断言 `pitchr = er + unearnedr + COALESCE(pendingr, 0)`、`er <= pitchr`、24 个球队口径 `Σ pitchr = 对手得分`。
- 验收：公开 API 12 场全部通过；245 场 靳皓然 R5/ER5、唐风 R1/ER1、肖罗衣 R9/ER9、彭建波 R4/ER3/UER1，页面合计恢复为电子科大 R6/ER6、锦江 R13/ER12。

后续验收必须同时跑两条链路：

1. 数据库：`docs/ops/er-audit-149.sql`（已改为旧列）。
2. 公开 API：`node scripts/audit/audit_stats_invariants.mjs --fetch --api-base https://bsdone.com/bsball-server --games-json _audit436/games.json`。它能发现“库里的新列已对平、页面读取的旧列没动”这类列名错位。

仍未覆盖：227/228/229 等没有 `bs_earned_run_play` 的旧场次，以及 235/248、246/249、252；这些场次缺少判定或快照，不能按本方案自动重算，需要单独的补录/人工核对。
