# 个人驾驶舱配置

## 表：bs_user_clubhouse_config

按“用户 + 租户”保存模块化驾驶舱的模块顺序、显示开关与数据选择；模块宽度由白名单固定。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigserial | 主键 |
| `user_id` | bigint | 用户 ID |
| `tenant_id` | bigint | 租户 ID |
| `config_json` | text | 校验后的 JSON 配置 |
| `config_version` | integer | 配置版本，首次为 1，每次保存递增 |
| `created_by` / `created_at` | 审计 | 创建人/时间 |
| `updated_by` / `updated_at` | 审计 | 更新人/时间 |
| `deleted_by` / `deleted_at` | 软删 | 预留；当前只更新不删除 |

唯一约束：`(user_id, tenant_id) WHERE deleted_at IS NULL`，索引名 `ux_bs_user_clubhouse_config_user_tenant`。

迁移：`V20261021180000__user_clubhouse_config.sql`。

## config_json 结构

```json
{
  "version": 2,
  "layout": "v3-modular",
  "modules": [
    { "key": "ranks", "enabled": true },
    { "key": "evaluation", "enabled": true },
    { "key": "performance", "enabled": true },
    { "key": "teams", "enabled": true },
    { "key": "schedule", "enabled": true },
    { "key": "about", "enabled": true },
    { "key": "recentGames", "enabled": true },
    { "key": "quickLinks", "enabled": true }
  ],
  "performance": { "metricKey": "batting.avg", "viz": "line" },
  "ranks": [
    { "metricKey": "batting.avg" },
    { "metricKey": "batting.h" },
    { "metricKey": "batting.obp" },
    { "metricKey": "batting.rbi" }
  ]
}
```

- `modules` 数组顺序即展示顺序；只持久化 `key` 与 `enabled`，宽度由 `ClubhouseModuleCatalog` 固定为 12/8/4。
- 服务端保存前用 `ClubhouseModuleCatalog` 校验模块白名单与重复项，用 `ClubhouseMetricCatalog` 校验指标白名单、图表兼容性、排名数量与重复项。
- 未提供的模块会按默认顺序补到数组末尾；八个模块始终完整落库。允许全部 `enabled=false`。
- `version:1` / `layout:v3-fixed` 旧配置读取时保留指标与排名选择，补默认模块并返回 v2；GET 不写库。
- 保存使用 PostgreSQL `ON CONFLICT (user_id, tenant_id) WHERE deleted_at IS NULL` 原子 upsert，避免并发首次保存撞部分唯一索引。
- 读取到非法/损坏 JSON 时回退默认配置但不在 GET 中写库；下次保存时覆盖。
- 默认排名不包含全垒打；全垒打只作为表现图可选指标，不进入队内排名。
- 本批不新增表或迁移，仍使用 `V20261021180000__user_clubhouse_config.sql`。
