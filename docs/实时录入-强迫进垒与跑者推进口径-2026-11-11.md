# 实时录入 · 强迫进垒与跑者推进口径（2026-11-11）

## 一、背景

旧逻辑在多条击球结果里把垒上跑者按“安打垒数/统一 +1”自动推走，再用「不进垒」把非强迫跑者退回。方向相反：非强迫局面应默认留垒，只有记录员明确拖拽进垒时才要求选原因。

本次按用户确认的 4 个口径统一：

1. 安打/失误/野手选择：挤出谁推谁；击球员到达的垒位及强迫链上的跑者自动前进，其余默认留垒。
2. 全垒打/三垒安打：规则必进，仍自动得分。
3. 牺牲打、暴投、捕逸：不再自动推进；改由拖拽选原因。投手犯规/不合法投球保留自动奖励一垒。
4. 满垒地滚球出局：三垒跑者自动回本垒，弹「安全/出局」确认，无「不进垒」。

## 二、强迫推进算法

纯函数：`bsball-frontend/src/utils/liveGameForceAdvance.js`。

- `resolveBatterForceAdvance({ batterBase, runners, batter })`：击球员到达 1/2/3/4 垒。
  - 原本在 `1..batterBase` 的跑者至少被挤到 `batterBase+1`；
  - 前方连续占垒的跑者按“领先跑者优先、后来者占近垒”继续前推；
  - 越过三垒进入 `homeRunners`，交给本垒确认（三垒安打/全垒打除外，自动得分）。
- `resolveGroundOutForceAdvance({ runners })`：打者在一垒出局；只有一垒有人的连续强迫链前进；满垒时三垒跑者进入本垒确认。
- 投手犯规/不合法投球仍沿用既有 `ai()`/`ti()` 奖励一垒，不纳入击球推进计划。

### 典型结果

| 场景 | 自动推进 | 留垒 |
|---|---|---|
| 仅二垒有人 + 一垒安打 | 打者到一垒 | 二垒跑者留二垒 |
| 一垒有人 + 一垒安打 | 一垒跑者到二垒 | — |
| 一垒+二垒有人 + 一垒安打 | 一垒→二垒、二垒→三垒 | — |
| 满垒 + 一垒安打 | 一垒→二垒、二垒→三垒、三垒回本垒（确认） | — |
| 仅二垒有人 + 二垒安打 | 二垒跑者到三垒 | — |
| 一垒+二垒有人 + 二垒安打 | 二垒跑者回本垒（确认）、一垒跑者到三垒 | — |
| 三垒有人 + 三垒安打 | 三垒跑者回本垒（自动得分） | — |
| 满垒 + 地滚出局 | 一垒→二垒、二垒→三垒、三垒回本垒（确认） | — |

## 三、入口改造

| 入口 | 新行为 |
|---|---|
| H1/H2/H3 | 使用强迫推进计划；非强迫跑者留垒；本垒确认只保留安全/出局 |
| HR/IPHR | 保留自动得分 |
| BB/HBP/IBB | 保留强迫链 |
| G | 只推进强迫链；满垒三垒自动回本垒并确认 |
| F/L/TAG | 不推进 |
| SF/SH | 不自动推进/得分；拖拽选「牺牲高飞推进」/「牺牲触击推进」 |
| E/FC | 使用强迫推进计划；本垒被迫得分进入安全/出局确认 |
| DP/TP | 去掉「不进垒」；本垒确认只保留安全/出局 |

## 四、拖拽原因

### 安全

- 安打推进（不计打点/有打点）【新增】
- 牺牲高飞推进（有打点）【新增】
- 牺牲触击推进【新增】
- 野手选择推进
- 传球失误推进、守备失误推进、同一 play 内失误推进、另一守备失误后再推进、牵制失误推进
- 趁传进垒
- 暴投 WP、捕逸 PB、守备大意 DI
- 盗垒成功/连续盗垒/盗本垒
- 上一棒内推进（不计打点/有打点/牺牲打）
- 回垒（安全返回）【替代“未进垒”】
- 其他

### 出局（非强迫）

- 盗垒失败（仅盗垒场景；捕手 C 首发且恰好两传才记 CS）
- 触杀出局、进攻方妨碍、申诉出局、其他
- 离垒过远出局：不需要；触杀出局已覆盖（菜单不提供）
- 封杀出局：非强迫列表不提供；同垒接杀回传的旧例外保留

### 同垒牵制暴传的操作流程

局面：投手对垒上跑者做牵制，牵制传球暴传，跑者安全并继续进垒；不是盗垒、不是安打。

1. 把跑者拖回**原垒同垒**，上半区选「安全」；
2. 原因选「投手牵制尝试」；
3. 牵制结果选「暴传失误推进」；
4. 点失误责任守备员（记 E）；
5. 点目标垒（二垒/三垒/本垒）完成推进。

这里没有拖拽目标垒，所以必须第 5 步选目标垒；目标/路径有人时按同一口径阻塞。拖拽路径选失误原因时则直接用拖拽目标垒，不重复选。

### 记账

- 安打推进得分选「有打点」才给上一棒打者记 RBI。
- 牺牲高飞得分选「牺牲高飞推进（有打点）」时给上一棒打者记 RBI；SF 已由击球结果记录。
- 若上一棒原本记成 F/L/G/TAG、尚未记 SF/SH，应选「上一棒内推进（牺牲打）」：由 `resolveSacrificeCredit` 补记 SF/SH、回减 AB，并在得分时记 RBI；已记 SF/SH 时不会重复补记。
- 牺牲触击推进不记 RBI。
- 失误得分仍按「正常防守下是否得分」判定 RBI。
- 暴投/捕逸/捕手妨碍推进不记 RBI；来源保留 WP/PB/INTERFERENCE，供 ER 归因。

## 五、已取消的“未进垒”选项

- 拖拽后退 `safe_retreat`「未进垒」→ 改为“回垒（安全返回）”。
- 安打/失误/野选本垒确认 `noscore`、`allowDidntScore`、「不进垒」按钮。
- 双杀结算 `runner3Decision=noscore`「不进垒·退回三垒」。
- 投手牵制「未造成进垒 / 出局」→ 改为「牵制未果（安全回垒）」。

- 纯函数单测：17 例（安打/二垒安打/三垒安打/全垒打/地滚/投手犯规）。

  - 满垒安打本垒确认：只弹安全/出局，无「不进垒」。
  - 既有跑者出局/双杀/盗垒/牵制/存盘重载回归。
- 构建：`npm run build` 通过。

## 七、本次不改 / 后续

- 拖拽时前方/目标垒有人一律阻塞，提示「前方垒位有人，请先处理前位跑者」，不再自动前推占垒者。
