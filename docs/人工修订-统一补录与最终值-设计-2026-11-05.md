# 人工修订：统一补录入口与“最终有效值”设计（草案）

- 日期：2026-11-05
- 状态：待审核（未实施）
- 关联：Issue #583（投手行无法删除/转记）、Issue #568（录错球员一键换人）
- 目标环境：赛后补录/复核；实时录入仍保留为现场记录入口

---

## 1. 背景

当前人工干预分散在多个入口、多张表、多套优先级与删除守卫中：

- 结果录入页：打者/投手/守备/捕手统计编辑；引擎场次 R/ER 只读（后来新增人工覆写）。
- LiveGame 赛后复核抽屉：ER 逐分判定覆写、投手 R/ER 覆写、守备补记 A。
- 后端：`bs_game_player_stat`、`bs_game_fielding_pos_stat`、`bs_earned_run_play/decision`、`bs_pitcher_run_override`、`bs_game_fielding_adjustment`、live snapshot。
- 删除守卫：引擎场次投手行要求“全零 + 无自责分判定”，但页面不暴露 `pitchPa` 等隐藏字段，也不支持判定改派，导致“明明清了还是删不掉”。

生产 261 是典型症状：16 号被误录为投手，21 号是正确投手；16 号行 NP/FO 等残留，删除被拦；R/ER 覆写只改合计，不改判定责任投手；页面又缺少“转记”入口。

Issue #568 则是另一个维度：整名球员从头到尾录错，需要把该球员的统计、守备、判定、现场记录一起换到正确球员。

## 2. 目标与非目标

### 目标

1. **人工修订只有一个入口**：以现有“赛事补录/编辑比赛结果”页为基础升级，ER 复核、守备补记 A、投手 R/ER、身份转记、审计都收进同一页。
2. **实时记录是基座，人工修订是最终值**：排名、评分、前端展示等消费方统一读取“最终有效值”。
3. **原始记录始终保留**：实时记录/引擎判定/基座统计不被人工修订覆盖，可审计、可回放。
4. **人工修订有留痕标志**：每个被人工改过的字段/行/判定都能看到来源、操作人、时间、原因、前后值、状态。
5. **一键转记**：覆盖“从头到尾选错人”和“单个投手行录错人”两类场景；不静默丢数据。
6. **删除可解释**：删除失败时明确列出剩余字段/判定/补记，并给出推荐操作（转记/清零/去复核）。
7. **保留既有体验**：汇总行、行高亮、列显隐/排序、行内输入、移动端布局等不回退。

### 非目标（本期不做）

- 不改变实时录入的现场操作方式。
- 不为了人工修订而关闭 ER 引擎；引擎仍负责实时/重建的基座计算。
- 不自动删除任何球员/统计行（除非用户在明确预览后确认）。

## 3. 现状与问题拆解

### 3.1 写路径

| 层 | 现有实现 | 问题 |
|---|---|---|
| 实时记录/引擎 | live snapshot、playEvents、ER 重建写 R/ER/UER/PENDING | 引擎与人工值混写在同一统计表 |
| 人工修订 | 结果页统计编辑、R/ER 覆写、判定覆写、守备补记 | 分散、优先级不统一、部分字段不可见 |
| 最终消费 | 统计表/判定表直接给排名、详情、门户 | 无法区分“原始值/人工值/失效值” |

### 3.2 典型冲突

- `pitchPa` 隐藏且不参与零判定 → 页面不能清零，删除守卫曾被迫忽略它。
- 判定只能改 EARNED/UNEARNED，不能改责任投手/作废 → 错人场景无法从根上修正。
- R/ER 合计覆写与逐分判定并存 → 合计可能“正确”，但判定仍挂在错误球员名下。
- 删除守卫只给一句“请先转记”，没有可执行入口。
- 身份转记会同时影响统计、守备位置、判定、现场快照；目前只处理其中一部分。

## 4. 总体设计：分层最终值

```
实时记录 / ER 引擎（原始基座，只追加/可回放）
        │
        ├── 基座统计快照（bs_game_stat_base / 历史）
        │
人工修订台账（统一 adjustment，字段/行/判定/身份转记）
        │  优先级：人工最终 > 人工修订 > 引擎
        ▼
最终有效值（effective；排名/评分/展示统一读取）
        │
        └── 审计视图（原始值、人工值、操作人、时间、原因、状态）
```

### 4.1 原始基座层（Raw/Base）

- 实时快照、Play 事件、ER 判定保持原样，不因人工修订被删除。
- 新增 **基座统计快照**：在引擎/实时写入统计行后，保留一份不可变的基座值（按球员行/版本）。
  - 建议表：`bs_game_stat_base`（game/team/player/is_pitcher、字段 JSON 或列快照、来源 LIVE/ENGINE/IMPORT、版本、创建时间）。
  - 目的：`bs_game_player_stat` 作为最终有效值可被人工覆盖，但仍能回答“实时记录当时是多少”。
- 历史场次没有基座快照时，标记为 `LEGACY`，不反推伪造原始值。

### 4.2 人工修订台账（Adjustment）

统一记录所有人工干预，不可硬删除，只能撤销/失效/被替代：

- 作用域：`PLAYER_STAT`（字段/整行）、`ER_DECISION`、`IDENTITY_TRANSFER`、`FIELDING_A`（守备补记，可复用现有表并挂接）。
- 类型：`ABSOLUTE`（绝对值，如 R/ER/PA）、`DELTA`（增减）、`TRANSFER`（源→目标）、`FINAL_LOCK`（该作用域人工最终；保存修订时即生效，不是额外的游戏级确认步骤）。
- 状态：`ACTIVE / REVOKED / INVALIDATED / SUPERSEDED`。
- 审计字段：`operator_id`、`operated_at`、`reason`、`source`、`before_value`、`after_value`、`related_play_id/source_event_id`、`note`。
- 建议表：`bs_game_stat_adjustment`；现有 `bs_pitcher_run_override`、`bs_game_fielding_adjustment` 作为领域子表保留或通过 `source_type/source_id` 挂接，避免一次性大迁移。

### 4.3 最终有效值（Effective）

- `bs_game_player_stat` 继续作为**最终有效值表**，排名/评分/前端展示默认读它，减少消费方改造。
- 写入顺序：
  1. 引擎/实时写基座快照；
  2. 应用 ACTIVE 人工修订；
  3. 生成/覆盖有效统计行（带 `manual` 标志/审计引用）。
- 人工最终（`FINAL_LOCK`）生效时，该作用域的引擎重算跳过该球员/行/判定；原始判定仍保留，但标记“非权威”。
- 删除球员行前只检查**有效值**是否全零 + 是否仍有有效判定/补记；失败时返回结构化明细（字段/判定数/补记数）而不是一句话。

### 4.4 ER 判定与人工最终

- `bs_earned_run_decision` 是原始判定，不删除。
- 人工修订支持：
  - 改 EARNED/UNEARNED（现有）；
  - 改责任投手（新增）；
  - 作废/标记误录（新增，保留原始行）；
  - 漏记跑者补记（可选；若实现，生成带审计的人工判定）。
- 投手 R/ER 人工最终：
  - 允许直接覆写 R/ER 合计；
  - 若与逐分判定不一致，保留判定用于审计，但有效值以人工最终为准，并显示“差异”标记；
  - 重算时跳过人工最终投手，避免下次重建冲掉。
- 若 16 号行仍有判定：删除/转记向导必须允许“把判定改派给 21 号”或“作废判定”，而不是只报错。

### 4.5 身份转记（一键换人）

- 新增 `IDENTITY_TRANSFER` 修订：源球员 → 目标球员，可勾选范围：
  - 打者/投手/守备（含捕手 PB/SB/CS）统计；
  - 逐位置守备；
  - ER 判定及责任投手；
  - live snapshot / Play 事件中的球员归属（第二阶段；实时 #568）。
- 转记是“写最终有效值 + 保留原始记录”，不是物理搬走原始行。
- 转记预览必须列出将移动的字段/判定/守备行及目标已有值冲突；目标已有值优先或由用户逐项选择。
- **转记与删除分开两个动作**：先完成转记（后端事务写修订台账 + 更新有效值）；转记成功后再单独弹窗询问“是否删除源行”，用户确认后才执行删除。不把删除和转记绑在同一个按钮动作里，也不静默自动删除。
- 源行原始值写入转记审计（前后值、操作人、时间、原因），现场快照/Play 原始记录保留。

### 4.6 PA / BF

- PA 与 BF 是同一口径（面对打席/轮击数），不再保留两个可独立编辑的隐藏值。
- UI 增加 PA 列，与 BF 双向同步；任一列编辑同时写两列。
- PA 纳入全零判定（因为现在可编辑/可清零）；删除诊断会显示 PA。
- 历史差异（如 261 的 PA11/BF0）在审计中可见；不强行改写历史基座。

### 4.7 优先级与失效

- 优先级：`人工最终（FINAL_LOCK） > ACTIVE 人工修订 > 引擎/实时基座`。
- 基座变化（半局重建、补录新 Play、重开比赛）时：
  - 受影响球员/判定的修订标记 `INVALIDATED` 并提示重新复核；
  - 不静默删除修订记录；
  - 最终锁定被打破时，比赛复核状态回到“需复核”。
- 最终确认后再次修改必须“重开复核”并填写原因。

## 5. 统一入口 UX

### 5.1 页面结构

以现有“编辑比赛结果/赛事补录”页为壳，保持：
- 顶部比赛信息/比分板；
- 打者/投手/守备表格；捕手 PB/SB/CS 并入守备表，不再单独设捕手页签；
- Totals 汇总行、行高亮、列显隐/排序、行内 input-number、批量选择；
- 移动端横向滚动与紧凑布局。

新增/整合页签：

1. 打者数据
2. 投手数据（含 R/ER、PA/BF、NP 等）
3. 守备数据（含捕手 PB/SB/CS；不再单独设捕手页签）
4. **ER 复核**（逐分判定、责任投手、作废、差异提示）
5. **守备补记 A**（失误 Play、补记、撤销）
6. **转记/身份修正**（源→目标、预览、范围勾选）
7. **修订记录/审计**（时间线、前后值、操作人、原因、状态）

LiveGame 的“比赛复核”只保留给进行中/现场使用；已结束比赛统一从“数据补录/复核”进入，不再维护第二套最终复核入口。统一入口上线后，比赛列表原有的“赛后复核”按钮入口去掉，改为“数据补录/复核”（原“编辑比赛结果”入口升级），避免用户在两套入口之间选择。

### 5.2 状态与留痕

- 顶部状态条：“实时记录为基座 · 人工修订为最终值”；显示比赛修订状态（未修订/已修订/需重审）。
- 单元格/行徽标：`人工`、`人工最终`、`差异`、`已失效`；点按展示审计摘要。
- 页脚“修订记录”显示最近变更；完整时间线在审计页签。
- 保存前显示 diff 预览：哪些球员/字段/判定会变化，是否影响排名。

### 5.3 删除诊断与推荐操作

删除投手行/球员行前，先做本地+后端双重诊断：

- 列出剩余数据：`FO=3、NP=27、PA=11`（带中文名）。
- 推荐操作按钮：
  - **转记到其他投手/球员**（打开转记向导）；
  - **清零这些字段**（明确确认，记录审计）；
  - **去 ER 复核**（如仍有有效判定）；
  - **去守备补记**（如仍有 A 补记）；
  - 取消。
- 后端错误也返回结构化明细（字段/判定数/补记数），前端不再只显示一句“请先转记”。

### 5.4 转记向导

1. 选源（当前高亮行/球员）；
2. 选目标（同队下拉，显示背号+姓名+P/位置）；
3. 预览：源值、目标现有、转记后；R/ER 标注“引擎/人工最终”；
4. 勾选范围（统计/守备/判定/现场记录，按阶段开放）；
5. 确认转记：后端事务写修订台账并更新有效值；源行保留。
6. 转记成功后单独弹窗：“已转记到 21号 崔铉，是否删除源行 16号 蔡昊伦？”→“暂不删除/删除源行”；删除是独立动作，不跟转记绑在一个按钮里。
7. 审计记录：源/目标、前后值、操作人、时间、原因；原始现场快照/Play 保留。

### 5.5 权限与审计

- 权限拆分：补录编辑、ER 复核、A 补记、身份转记、审计查看。
- **保存人工修订即作为最终有效值**，不再设置“确认最终”门槛；排名/评分/展示直接使用保存后的有效值。
- **允许反复修订**：同一字段/球员可多次保存，每次保存都立即写库并新增一条审计记录（前后值、操作人、时间、原因）；不要求一次改完，也不覆盖历史修订记录。
- 如需撤销，通过修订台账撤销/失效，不静默覆盖。
- 重开比赛/重建半局导致修订失效时提示“需重审”，修订记录保留。

## 6. 计算与消费链路

需要逐项盘点并统一到有效值：

- 比赛详情/盒子比分；
- 球员赛季统计、生涯统计；
- 球队/联赛排名、投手榜、打者榜；
- 个人驾驶舱、门户球员页；
- 评分/奖项/导出数据。

原则：

- 普通展示/排名只读**最终有效值**；
- 管理端可读原始基座 + 修订台账（审计）；
- 任何直接聚合 `bs_earned_run_decision` 的接口需改为读取有效判定/有效投手统计，避免人工修订后排名的 R/ER 与详情不一致；
- 增加一致性校验：有效 R = ER+UER+PENDING、ER≤R、PA=BF、判定合计与投手 R 对账（允许人工最终差异，但必须可见）。

## 7. 数据表/API 变更（建议）

### 7.1 表

- `bs_game_stat_base`：基座统计快照（不可变，按版本）。
- `bs_game_stat_adjustment`：统一修订台账（作用域/类型/前后值/状态/审计）。
- `bs_game_review`：比赛复核状态（未复核/已修订/已最终/需重审、锁定人/时间/原因）。
- `bs_earned_run_decision`：保留原始行；新增判定改派/作废的关联（通过 adjustment 或新增 `superseded_by`）。
- `bs_game_player_stat`：保留为最终有效值表，新增 `manual_version`/`manual_flags`（或通过关联查询）。
- 现有 `bs_pitcher_run_override`、`bs_game_fielding_adjustment`：迁移映射或作为 adjustment 的领域子表挂接。

### 7.2 API

- 统一修订接口：`POST /game/{id}/adjustments`（批量 diff）、`POST /game/{id}/adjustments/{id}/revoke`、`GET /game/{id}/adjustments`。
- 转记：`POST /game/{id}/adjustments/transfer`（源/目标/范围/冲突策略）。
- 删除诊断：删除接口返回结构化 `blockers`（字段/判定/补记），或新增 `GET /game/{id}/stat-rows/{rowId}/delete-check`。
- 复核状态：`GET/POST /game/{id}/review`（开始/保存/最终/重开）。
- 原统计列表返回 `manual`/`manualFinal`/`adjustmentId` 标记（管理端），公共展示用有效值。

## 8. 迁移与兼容

1. 现有 `bs_pitcher_run_override`、`bs_game_fielding_adjustment`、判定覆写先保留，读时与 adjustment 合并；新功能只写新台账。
2. 历史场次 `bs_game_player_stat` 视为已有有效值；没有基座快照的标 `LEGACY`，不伪造原始值。
3. 新场次在实时保存/重建时写基座快照。
4. 排名/展示改造前先做只读对账：有效值 vs 现有统计，确保迁移不改变已结束比赛结果。
5. API 兼容：旧字段保留，新增标记字段；前端按能力渐进切换。

## 9. 分期计划

### P1（先解决 261，低风险）

- 投手表新增 PA 列，PA/BF 双向同步；PA 纳入全零判定。
- 投手行“转记”（当前高亮行 → 同队目标 → 预览 → 确认转记）：转记完成后**单独弹窗**询问是否删除源行；删除是独立动作，不与转记绑在同一按钮/事务里。
- 删除前诊断：列出剩余字段 + 推荐“转记/清零/去复核”。
- 保留 Totals、高亮、列设置等既有体验。
- 后端新增最小转记接口 + 转记审计（源行前后值、操作人、时间），PA 零判定；P1 仅覆盖统计 + 逐位置守备，ER 判定/现场记录放后续。

### P2（统一入口与最终值）

- 结果补录页整合 ER 复核、A 补记页签；LiveGame 最终复核入口收敛。
- 基座快照 + 修订台账 + 人工最终标志/审计；排名/展示逐步切到有效值。
- 删除诊断接入判定/补记；ER 判定改派/作废。

### P3（身份转记与审计中心）

- 整名球员身份转记（统计/守备/判定/现场记录），覆盖 #568。
- 权限、修订时间线/审计中心；重开复核提示。
- 全部消费方一致性验收与性能优化。

## 10. 测试/验收

- 261 场景：16→21 转记，NP/PA/FO/R/ER 正确，源行可删，原始记录保留。
- 261 删除诊断：列出 FO/NP/PA，点“转记”进入向导。
- PA/BF 同步：改任一列两列一致；PA-only 行可清零后删除。
- ER：判定改派/作废后有效 R/ER 正确；排名/详情一致；原始判定仍可查。
- A 补记：补记/撤销后有效守备统计正确；源 Play 失效处理。
- 审计：每次人工修订有前后值/操作人/原因/状态，可撤销；失效有提示。
- 回归：Totals、行高亮、列显隐/排序、移动端、现有结果录入保存。
- 权限：不同角色只能做授权操作；人工修订不可静默覆盖，必须有审计。

## 11. 已确认决策与剩余风险

已确认：

1. **转记与删除**：先完成转记；转记成功后单独弹窗询问是否删除源行。删除是独立动作，不与转记绑在同一按钮/事务里；不静默自动删除。
2. **最终值生效时机**：保存人工修订即作为最终有效值，不再设“确认最终”门槛。
3. **转记范围**：P1 先覆盖统计 + 逐位置守备；ER 判定改派/现场记录放 P2/P3。
4. **历史数据**：只对新场次写基座快照；历史场次标 `LEGACY`，不伪造原始值。

剩余风险/待定：

- 统一台账 vs 保留领域表：建议新台账 + 现有表挂接渐进迁移。
- ER 人工最终与逐分判定冲突：允许差异但必须显示；默认人工合计优先，需在 P2 细化。
- 排名切换：历史排名是否重算，还是只影响后续查询，P2 前确认。
- 性能/审计增长：修订记录索引与归档策略。

## 12. 推荐结论

- 采用“实时基座 + 人工修订台账 + 最终有效值”的分层模型，而不是把人工值直接写死进统计表。
- 以赛事补录页为唯一人工修订入口，ER/A 复核、转记、删除诊断、审计全部收进同页；保留现有汇总行/高亮/列设置。
- P1 先做 PA + 转记（确认后同事务删除源行）+ 删除诊断，解决 261；P2 再做基座快照/最终值/审计与 ER 判定改派；P3 覆盖整名球员身份转记与审计中心。
- 所有排名/评分/展示只读最终有效值；原始实时记录永久保留，人工修订全部留痕。
