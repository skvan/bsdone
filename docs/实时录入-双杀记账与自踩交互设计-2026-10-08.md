## 二、记账新规则（③-a，拟）

**适用**：`flow.type ∈ {DP, TP}`；输入为**原始链（未压缩）**。

### 算法（可读伪码）

```
输入: steps(原始守备位数组), outs(出局数: DP=2, TP=3)
1) 相邻重复合并：遍历 steps，若 steps[i]==steps[i+1] 记为一次"自踩动作"并跳过重复项；
   得到动作序列 A = [a1..ak]（ai = {pos, selfstep})
2) 统计:
   - k == 1（原始全同，如 [1B,1B]）：
       该守位 PO += outs（独力：PO×2/×3）；A 不记
   - k == 2：
       a1: PO+1, A+1（若 a1.selfstep 同样为 PO+1,A+1）
       a2: PO+1
   - k >= 3：
       a1: 若 selfstep → PO+1,A+1；否则 A+1
       a2..a(k-1): PO+1, A+1
       ak: PO+1
```

### 全场景验证表

| 场景 | 原始链 | 动作序列 | 统计结果 |
|---|---|---|---|
| 6-3 | `[SS,1B]` | SS,1B | SS:PO+A；1B:PO ✅ |
| 6-4-3 | `[SS,2B,1B]` | SS,2B,1B | SS:A；2B:PO+A；1B:PO ✅ |
| 6-6-3 | `[SS,SS,1B]` | SS(self),1B | SS:PO+A；1B:PO ✅ |
| 独力双杀 | `[1B,1B]` | 1B(self)唯一 | 1B:PO×2 ✅ |
| 6-4-3-3(4项) | `[SS,2B,1B,1B]` | SS,2B,1B(self) | SS:A；2B:PO+A；1B:PO ✅ |
| 自踩+两传(超范围) | `[SS,SS,2B,1B]` | SS(self),2B,1B | SS:PO+A；2B:PO+A；1B:PO（3个封杀点>DP出局数——**列为限制，按此统计但属超语义输入**） |

### 实现

- 抽取纯函数 `computeChainFieldingStats(type, steps) → Map<pos,{po,a}>` 至 `src/utils/`（可单测，脱离组件）。
- `fp()`/`Dn()` 调用调整：**DP/TP** 用新函数；其余类型继续原 `Dn`（保持现状）。
- 兼容：历史已保存数据**不回填**；undo/快照结构不变（记账是结算时刻计算，不落链外数据）。

## 四、自踩/触杀交互（④，拟）

### 交互流程

```
链进行中（如双杀已选落点；**仅链尾“持球守备员”可拖——无球者拖动不触发任何动作，2026-10-08 裁决**）：
1. 按住持球守备员拖动（复用 FielderDrag 框架；**按住即拖，无长按**——2026-10-08 裁决）
2. 拖到垒包附近（4 垒包坐标，命中半径 ≈30）→ 高亮该垒包
3. 松手 → 弹层「该动作记录为：封杀出局 / 触杀出局 / 取消」
4. 选择后：记录"自踩/触杀动作"（链追加该守位一次 + 动作类型），球高亮该垒位
5. 继续点选其他守备员=传球（现状）；或点「完成记录」收尾
```

### 数据与兼容

- `flow.steps` 保持 `string[]`（不改结构）；新增并行 `flow.stepActions?: (null|{action:'force'|'tag', base:number})[]`（长度与 steps 对齐，缺省 null=普通动作；兼容旧快照的字符串 `'force'|'tag'`，无垒包时按 §四之二 推断）
- **undo**（`structuredClone(flow)`）与**快照**（`JSON.stringify`）自动携带新字段；旧数据无该字段 → 全部按普通动作处理
- 结算/文本/记账联动：**2026-10-23 起 stepActions 正式消费**——FC 取最后一步自踩动作驱动出局垒/触杀封杀与日志文案；无自踩时沿用下一垒/封杀原口径；DP/TP 记账仍走既有 `computeChainFieldingStats`，不受影响
- 手势共存：BIP_HIT_PENDING 拖=落点调整（现状）；链中拖=自踩动作（新增）；链中点=传球（现状）——三态互斥由 `flow.type` 分流

### 边界

- 命中半径、同垒多守备员（命中最近的）、误拖（松手不在垒包=取消无副作用）、与菜单拖拽优先级、超长链（≤8 现状上限）
- 移动端触控：长按阈值复用现有（mouse 220ms / touch 280ms）

### 四之二、单出局链自踩/出局垒/记账（2026-10-23 追加）

**背景**：5-2-5 回三垒触杀被写成「5-2-5-5 / 于本垒被封杀」，且三垒手同时记 A 与 PO。

**规则**
1. 链条规整：相邻重复（自踩动作）合并为一次，`[5,2,5,5] → [5,2,5]`；显示与记账共用。
2. 出局垒/方式判定（`resolveSingleOutChain`）：
   - 最后一步有自踩动作 → 采用所选 `{action, base}`；
   - 无自踩动作 → 沿用原口径：起始垒+1、封杀；**不按末位守备员覆盖垒反推**，避免把延长传球链（如 6-4-3 的末尾回传一垒）误判为回垒触杀；
   - 旧快照仅有动作字符串时保留动作，垒包沿用下一垒。
3. 记账（`computeSingleOutChainStats`）：末位 PO；前面不同守位各 1A；**已得 PO 的同人不再记 A**。适用于 G/SH/FC/触杀封杀夹杀等所有单出局链；DP/TP 不变。
4. 文案：末位触杀写「接球触杀」，封杀按原规则写「踏垒封杀」（单点独力为「接球封杀」）；跑者行写「于X被触杀/封杀出局」；因得 PO 而不记 A 的传球行只写「接球传X垒」，不带统计标注。
5. FC 被迫进垒修正：三垒跑者仅在一、二垒均有人（满垒）时才被迫进本垒；原判据仅看二垒有人，会把非被迫进垒误记得分/RBI。

**样例（本次缺陷）**
- 输入：三垒跑者，链条 5-2-5-5，最后一步自踩 5 选触杀、垒包三垒
- 输出：链条 5-2-5；5 三垒手首传「接球传本垒」不记 A；2 捕手「接球传三垒（助杀 A）」；5 三垒手「接球触杀三垒跑者（刺杀 PO）」；跑者「于三垒被触杀出局（5-2-5，野手选择 FC）」
- 记账：5 PO×1；2 A×1

**兼容/回填**：仅影响新记录；历史比赛日志与统计不回填。DP/TP 仍允许同一人因不同出局点分别记 PO/A。

## 七、双杀出局改由拖拽记录（2026-10-31，#530 最终口径）

### 问题

原结算在 `LiveGame.js` 的 `bt()` DP/TP 分支和 `fp()` 中写死「打者在一垒出局 + 一垒跑者在二垒出局」，再把二垒跑者推到三垒。传球链只参与守备统计，不决定出局归属；因此 6-5-4（三垒、二垒封杀，打者上一垒）会被结算成「打者 + 一垒跑者出局」。按本系统口径，双杀打者即使上一垒也记 GDP，但出局归属仍必须由拖拽决定。

### 入口门槛

- **双杀要求一垒有人**：一垒跑者被迫进二垒，才存在两个被迫出局点。仅二垒/三垒有人且非被迫进垒时不算双杀，按两次单独出局记录。
- **三杀要求一、二垒都有人**。

### 交互（最终）

1. 传球链与出局点是两个独立数组：`flow.steps` 只记纯传球链（6 → 4 → 3），`flow.dpOuts` 记出局点（守备员 + 垒包 + 链上位置）。
2. 可以先点完整条链，再拖链上任一守备员到垒包记录出局；也可以边点边拖。例如 6-4-3：先点 6、4、3，再拖 4 到二垒（出局 1）、3 到一垒（出局 2）。
3. 拖到垒包直接记一个被迫进垒的封杀出局点，不再弹触杀/封杀选择（双杀=两个被迫进垒的封杀）。
4. 第二出局后仍可继续点选下一传延长传球链，或点「完成记录」。
5. 「修改出局」仍可逐项改已记录出局点的垒包/跑者。

### 结算口径

- 出局跑者取该垒的被迫进垒者：一垒=打者、二垒=一垒跑者、三垒=二垒跑者、本垒=三垒跑者；没有对应被迫跑者时提示未决，不退到触杀。
- 打者只在一垒出局点被记录时出局；否则安全上一垒，**仍记 GDP（本系统口径）**；打席结果也按双杀记录，不再记 FC。
- 守备统计只取到最后一个出局点的链；第二出局后的延长传球不参与 DP 统计。
- 同一守备员在一垒的第二次出局（如 3-3 触杀）不是被迫进垒，提示未决，不按双杀结算。
- 三垒跑者仍保留得分/留垒确认；双杀打者出局时跑回本垒的得分不计 RBI。

### 日志

- 主行：`打者 (#32): 6-4-3 传杀 双杀（打者出局，GDP +1）`；打者安全上一垒时写 `（打者上一垒，记 GDP）`。`Rt` 会附本棒次/累计出局数。
- 出局行：每名出局跑者一行，含垒包、守备员姓名/背号、完整链，例如 `二垒跑者 (#26) 于三垒被 主3B (#5) 封杀出局（6-5-4）`。
- 推进：剩余跑者的进垒单独成行，例如 `双杀推进：二垒跑者 ... 进三垒 — 安全`；三杀时写「三杀推进」；三垒跑者得分/留垒仍按确认记录。
- 显示顺序：主行摘要 → 第 1 个出局 → 第 2 个出局 → 剩余跑者推进。

### 守备统计核验

| 场景 | 刺杀/助杀/DP | 未参与守备员 | 打者 |
|---|---|---|---|
| 6-5-4 | 6 A+DP；5 PO+A+DP；4 PO+DP | 1B、P、C：PO/A/E/DP 均为 0；全员守备 IP +0.2 | AB+1、GDP+1；打者上一垒 |
| 6-4-3 | 6 A+DP；4 PO+A+DP；3 PO+DP | 3B、P、C：PO/A/E/DP 均为 0；全员守备 IP +0.2 | AB+1、GDP+1；打者出局；二垒跑者进三垒 |

### 兼容

- 新流程 `flow.steps` 纯传球链 + `flow.dpOuts` 独立出局数组；旧快照的重复 steps + stepActions 仍按旧路径兼容；`dpOverrides` 只随 flow 深拷贝，历史数据不回填。
