## 四、精确重算方法

使用 `docs/ops/er-audit-149.sql`：

```sql
BEGIN TRANSACTION READ ONLY;
-- decisions：按 responsible_pitcher_id 汇总 EARNED/UNEARNED/PENDING
-- 与 bs_game_player_stat.pitch_r/er/unearned_r/pending_r 对比
-- 输出 verdict：OK / RECALCULABLE_DIFF / ER_GT_R / PENDING_REVIEW /
--              NO_DECISIONS / MISSING_STAT_ROW
ROLLBACK;
```

运行：

```bash
PGPASSWORD="$PG_PASSWORD" psql -h "$PROD_HOST" -U "$PG_USER" -d "$PG_DB" \
  -v ON_ERROR_STOP=1 -f docs/ops/er-audit-149.sql > er-audit.out
```

判读：

| verdict | 含义 | 处理 |
|---|---|---|
| `OK` | 库内 R/ER/UER/PENDING 与逐分判定一致 | 无需处理 |
| `RECALCULABLE_DIFF` | 有逐分判定，但库内累计值不一致 | 可用判定重算回填（需另行批准写库） |
| `ER_GT_R` | 库内 ER 大于失分，硬矛盾 | 视为数据错误，优先修复 |
| `PENDING_REVIEW` | 存在 PENDING 判定 | 先人工覆核，再重算 |
| `NO_DECISIONS` | 有引擎事件但无逐分判定 | 检查半局是否完整重建/是否有得分未挂接 |
| `MISSING_STAT_ROW` | 有判定但投手统计行缺失 | 先补投手行，再重算 |

## 五、限制

1. 本报告没有 DB 只读连接，无法给出 `calc_*`；只能用 `ER<=R`、`R=ER+UER+PENDING` 判断库内值自相矛盾。
2. 没有 `bs_earned_run_play` 的 legacy 场次无法用判定重算；应在 SQL 末尾的 `NO_ENGINE_DATA` 查询中单独列出，人工核对或保留原值。
3. 历史数据回填不在本次代码修复内；本次只交付只读脚本与报告，任何写库都需要另开任务、备份和回滚方案。
4. 引擎场次的 ER/R 在“录入比赛结果”页已改为只读；逐分判决可通过 `PUT /game/{id}/earned-runs/decisions/{decisionId}` 覆核，但该接口只能改已有判决，不能补录缺失的 playEvent。复杂局面（野手选择、触杀/封杀、妨碍、申诉、多跑者推进）若引擎漏记，需要先补 playEvent 再重建；这是后续 #149 二阶段的工作。
5. 本次通过 `@DynamicUpdate` 防止 saveLive/saveResult 把旧 ER 列回写，但 ER 引擎自身的半局重建/人工覆核仍是 read-modify-write；多端并发重建同一场时仍可能丢增量，后续需要 `@Version` 或原子 `SET er = er + ?` 更新（#149 引擎层）。
