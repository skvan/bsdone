## 二、数据模型与迁移

### 2.1 新表 `bs_league_special_rule`

```sql
CREATE TABLE IF NOT EXISTS bs_league_special_rule (
    id          BIGSERIAL PRIMARY KEY,
    tenant_id   BIGINT NOT NULL,
    league_id   BIGINT NOT NULL,
    rule_key    VARCHAR(64) NOT NULL,
    enabled     BOOLEAN NOT NULL DEFAULT FALSE,
    created_by  BIGINT,
    created_at  TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_by  BIGINT,
    updated_at  TIMESTAMP,
    deleted_by  BIGINT,
    deleted_at  TIMESTAMP,
    CONSTRAINT uk_bs_league_special_rule UNIQUE (league_id, rule_key)
);
COMMENT ON TABLE  bs_league_special_rule IS '联赛级特殊规则开关：行存在=以记录为准，无记录=默认值';
COMMENT ON COLUMN bs_league_special_rule.rule_key IS '规则键：extra_batter / force_half';
```

- **取值语义**：无记录 = 默认（`extra_batter` false、`force_half` true）；有记录 = 以记录为准（支持显式关闭）。规则行只写不删（无软删语义，`deleted_*` 恒空）。
- 落点：`model/entity/LeagueSpecialRule.java`（继承 BaseEntity，审计列与实体全量一致）+ `repository/LeagueSpecialRuleRepository.java`。
- 迁移文件：`V20261015100000__league_special_rule.sql`（建表 + 回填同文件；幂等、`COMMENT ON` 对齐先例 `V20260930150000__tenant_role_menu_config.sql`）。
- 规则键集中定义于 `LeagueSpecialRuleService` 常量，避免散落字符串。

### 2.2 存量白名单回填（同迁移文件，幂等）

两路证据 UNION → 经 `bs_event` 取 `league_id` → 回填 `extra_batter=true`：

```sql
INSERT INTO bs_league_special_rule (tenant_id, league_id, rule_key, enabled, created_at)
SELECT DISTINCT e.tenant_id, e.league_id, 'extra_batter', TRUE, CURRENT_TIMESTAMP
FROM (
    -- 证据 1：打序统计超默认（棒 >9 / 垒 >10）
    SELECT g.event_id
    FROM bs_game_player_stat s
    JOIN bs_game g ON g.id = s.game_id
    WHERE (g.game_mode = 'BASEBALL' AND s.batting_order > 9)
       OR (g.game_mode = 'SOFTBALL' AND s.batting_order > 10)
    UNION
    -- 证据 2：阵容快照（v1）homeLineup/awayLineup 数组长度超默认
    SELECT g.event_id
    FROM bs_game g
    WHERE g.live_snapshot_json LIKE '{%'
      AND ((g.game_mode = 'BASEBALL'
            AND (jsonb_array_length((g.live_snapshot_json::jsonb) -> 'homeLineup') > 9
              OR jsonb_array_length((g.live_snapshot_json::jsonb) -> 'awayLineup') > 9))
        OR (g.game_mode = 'SOFTBALL'
            AND (jsonb_array_length((g.live_snapshot_json::jsonb) -> 'homeLineup') > 10
              OR jsonb_array_length((g.live_snapshot_json::jsonb) -> 'awayLineup') > 10)))
) x
JOIN bs_event e ON e.id = x.event_id AND e.league_id IS NOT NULL
WHERE NOT EXISTS (
    SELECT 1 FROM bs_league_special_rule r
    WHERE r.league_id = e.league_id AND r.rule_key = 'extra_batter'
);
```

- 快照行数组长度 = 实际人数（归一化后行数 ≥ 满员时才增长）；软删/空串守卫在实施时按列现状补全（`deleted_at IS NULL`、`jsonb_typeof` 守护）。
- 幂等、可重复执行；未挂联赛的赛事跳过（保持默认口径）。

## 四、前端规则层（#274）

### 4.1 starterFieldingValidation.js

- 合法位置集合：棒球侧加 `EP`（`_` 映射 / `v` 合法集 / `Q` 的棒球集合 / 归一化）；垒球集合不变。
- 函数签名扩展（`opts = {extraBatter:false}`，**默认关闭、fail-closed**）：

| 函数 | 行为 |
|---|---|
| `getRosterSizeRange(mode, extraBatter)` | 棒球 `{min:9, max: extra?12:9}`；垒球 `{min:10, max: extra?11:10}` |

- **实施口径（2026-10-15 裁定）**：不改全局 `POSITION_LABELS`——EP 标签为 Games.js 局部方案（`ge` computed 按模式补 EP + `Me()` 对 `EP` 特判渲染 `EP (额外打击者)`），避免 EP 泄漏到报名类等位置下拉；位置下拉仍按模式过滤：棒球含 EP、垒球不含。

### 4.3 useLineupBoard.js

- 入参：`useLineupBoard(mode, teamId, opts)`（`opts.extraBatter` 响应式）。
- 上限：`baseCount` 不变；`maxCount = 开关 ? 绝对上限(棒 12 / 垒 11) : base`。

## 九、验收清单（合并 #275 + #274，测试人员照做）

前置：租管账号 + 超管账号；管理后台 → 联赛页配置规则；赛程 → scheduled 比赛 → 编辑阵容。

1. **默认口径**：未配置联赛的赛事，阵容页棒球打线超 9 人被拒，提示「该联赛未开放 EP 制（额外打击者），请联系管理员」；垒球超 10 人同理。
2. **租管开启**：打开 `extra_batter` → 同联赛棒球可到 10-12 人（11 人=8守位+P+DH+EP；12 人=再加 1 EP；第 13 人被拒）、垒球可到 11 人；提示消失。
3. **组合矩阵**：8 守位不全 / 双 DH / EP 超 3 / 无 P 且无 DH → 拒绝；`P+8+EP`、`DH+8+EP` 等合法组合通过。
4. **打序轮转**：连续推进打席越过第 9 棒，第 10/11/12 棒依次上场，名称与打序一致。
5. **恢复路径**：11/12 人阵录入若干打席 → 退出 → 「继续录入」→ 打线人数与顺序完整（不丢人）。
6. **结果录入页**：手动录入比赛结果时打序可选到 12；位置下拉可选 EP（垒球不出现 EP）。
7. **关闭强制换局**：联赛关闭 `force_half` → 该联赛录入页齿轮面板无「强制换局」；其他联赛不受影响。
8. **跨租户隔离**：租管修改非本租户联赛规则 → 403；超管可修改任意联赛。
9. **未挂联赛赛事**：默认口径（EP 关、强制换局开）。
10. **存量迁移**：迁移后原含 10 人棒球阵 / 11 人垒球阵的联赛 `extra_batter=true`（含仅保存过阵容草稿的）；其他联赛默认关闭；脚本可重复执行。
11. **不回溯**：历史比赛数据、已保存阵容不变。
12. **后端**：11/12 人阵保存不报「守备位置重复」；EP 排第 1 棒也可保存成功。

回归点：9 人棒球（投手制/DH 制）、10 人阵（P+8+DH）行为不变；垒球 10 人阵不受影响；阵容模板应用/草稿快照/开始录入/继续录入链路正常；实时观赛页展示正常；结果页排序、模板应用、批量删除正常。
